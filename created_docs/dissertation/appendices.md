# Appendices

## Appendix A — Research Instrument: The Eight Psychometric Constructs

The local model is fitted on eight constructs derived from the Sri Lankan survey instrument [@kanchana2023]. Each construct is computed as the **arithmetic mean of its constituent Likert items**, each item scored 1–5. The same definition is applied in the research pipeline (`scripts/preprocess_raw.py`) and in the deployed product's Pulse Check scoring, which is what makes train/serve parity possible (§4.7).

**Table A.1 — Construct composition in the source instrument**

| Code | Construct | Items | Role |
|---|---|---:|---|
| JS | Job Satisfaction | 9 | Predictor |
| WLB | Work-Life Balance | 5 | Predictor |
| H | Happiness | 5 | Predictor |
| MS | Management Support | 5 | Predictor |
| CM | Career Management | 4 | Predictor |
| IWB | Innovative Work Behaviour | 4 | Predictor |
| LMX | Leader-Member Exchange | 4 | Predictor |
| CWS | Co-Worker Support | 4 | Predictor |
| ET | Employee Turnover Intention | 4 | **Outcome** |

The outcome variable is the ET composite. `Attrition_binary` is defined as ET ≥ 3.5 on the 1–5 scale, yielding 33 positive cases in 230 records (14.3%). This cut-point is a design choice, and §5.8 reports model behaviour across alternative cut-points rather than relying on it.

**Deployment note.** The Pulse Check implemented in the product uses **two items per construct**, not the full battery above. This shortening was a deliberate trade — a 16-item weekly form is answerable, a 40-item one is not — and its consequence is disclosed wherever the Pulse Check is discussed: the short form is a noisier estimate of each construct than the instrument it derives from, and its internal consistency is unassessed because no real responses have been collected (§6.3).

## Appendix C — Source Code, Data and Artefact Availability

**Table C.1 — Datasets**

| File | Records | Role |
|---|---:|---|
| `data/nexus_hr_master_dataset.csv` | 2,820 | Training (Saudi real 1,191 + Russian real 1,129 + synthetic 500) |
| `data/validation_srilanka.csv` | 230 | Held-out Sri Lankan validation; never used in training |
| `data/benchmark_ibm.csv` | 1,470 | Published comparison only |
| `data/calibration_params.json` | — | Logistic coefficients fitted on 2,550 real records |

**Pipeline.** The data pipeline is five Python scripts run in order — `download_datasets.py`, `preprocess_raw.py`, `calibrate.py`, `generate_synthetic_data.py`, `merge_and_clean_data.py` — followed by `train_model.py`, which produces both the transfer and local models together with the SHAP outputs reproduced as Figures 5.1 to 5.5. Each evaluation question in Chapter 5 has its own script and emits a machine-readable JSON report; the figures in this dissertation are generated by those scripts rather than drawn by hand.

**Inference service.** `ml_service/` is a FastAPI application deployed to Cloud Run with authenticated access only, serving `/predict/local` and `/predict/transfer`. Its preprocessing mirrors `train_model.py` exactly, and its `requirements.txt` pins the scikit-learn version used in training, because a version mismatch silently breaks model deserialisation.

**Product integration.** The HR platform consuming these predictions is maintained in a separate repository and integrates over the HTTP API boundary rather than by code sharing. The attrition proxy, the risk card and the Pulse Check described in §4.6 and §4.7 were delivered as pull requests against that repository and are live on its development deployment.

**Reproducibility caveat.** Trained model bundles and generated report figures are excluded from version control by design; they are reproducible from the scripts and the datasets above. The two real international datasets are redistributed under their original licences and were obtained from their published sources rather than mirrored here.
